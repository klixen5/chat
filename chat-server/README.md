# Сервер учебного чата

Готовый backend для твоего React-приложения: **Express + PostgreSQL + обычный WebSocket**. Docker не используется. Фронтенда в этой папке нет — его реализуешь ты.

## Запуск одной командой

Из любого места в терминале:

```sh
npm --prefix ~/Desktop/chat-server start
```

Или открой эту папку в редакторе и выполни `npm start` во встроенном терминале.

Команда сама:

1. Установит зависимости при первом запуске, если их ещё нет (нужен интернет).
2. Подготовит отдельную локальную PostgreSQL в `.local/postgres`.
3. Запустит её на `127.0.0.1:55432`, создаст базу `chat`.
4. Создаст таблицы и комнаты `javascript`, `react`, `algorithms`.
5. Запустит Express на `http://127.0.0.1:3001` и WebSocket на `ws://127.0.0.1:3001/ws`.

Нужны Node.js **22.13+**, npm и установленные PostgreSQL-инструменты `initdb`, `pg_ctl`, `psql`. На твоём компьютере они уже найдены: Node.js 26 и PostgreSQL 17. Docker и глобальная установка npm-пакетов не нужны.

Проверь в браузере: [состояние сервера](http://127.0.0.1:3001/api/health), [комнаты](http://127.0.0.1:3001/api/rooms).

**Остановка — Ctrl+C в терминале сервера.** Запущенная этой командой PostgreSQL тоже остановится; история останется на диске. Следующий `npm start` откроет ту же базу. Чужая PostgreSQL на порту 5432 не используется и не изменяется.

## Что уже реализовано

- Три готовые комнаты, переключение между ними.
- Вход под именем без регистрации и пароля; имя привязано к соединению на сервере.
- История сообщений в PostgreSQL, загрузка предыдущих и пропущенных сообщений.
- Доставка новых сообщений всем подключённым участникам комнаты, включая отправителя.
- Подтверждение сохранения и защита от дубликатов при повторной отправке.
- Проверка имени, текста, UUID; понятные JSON-ошибки.
- CORS для локального React/Vite; проверка Origin при WebSocket-подключении.
- Ограничение размера событий и частоты отправки, heartbeat, корректная остановка.

Начальная история пустая. Напиши сообщения из своего интерфейса или воспользуйся примером в документации.

## Документация для фронтенда

Начни с **[docs/API.md](docs/API.md)**. Там описаны запросы, события, примеры ответов, обработка ошибок, порядок подключения и восстановление после обрыва связи.

Дополнительно:

- [types/api.d.ts](types/api.d.ts) — типы данных и событий для TypeScript, их можно скопировать в свой фронтенд.
- [requests.http](requests.http) — REST-запросы для расширения REST Client или ручной проверки.

Тебе не нужны `pg` или библиотека `ws` во фронтенде. Используй браузерные `fetch` и `WebSocket`. Socket.IO с этим сервером несовместим.

## Настройки

Обычно ничего настраивать не нужно. При необходимости скопируй `.env.example` в `.env` и измени значения. Переменные окружения терминала имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | Порт Express и WebSocket |
| `HOST` | `127.0.0.1` | Адрес сервера |
| `LOCAL_PG_PORT` | `55432` | Порт отдельной локальной PostgreSQL |
| `PG_BINDIR` | Поиск в `PATH` | Папка с `initdb`, `pg_ctl`, `psql` |
| `DATABASE_URL` | Не задана | Подключение к своей существующей базе вместо автоматической |
| `CLIENT_ORIGINS` | Локальные HTTP/HTTPS-адреса | Разрешённые адреса фронтенда через запятую |

Если задан `DATABASE_URL`, автоматическая PostgreSQL **не запускается** и не останавливается. База по этому адресу должна уже существовать; таблицы и комнаты сервер создаст сам. Подключение выполняется через библиотеку `pg` и параметризованные SQL-запросы.

Для собственной базы после установки зависимостей есть также `npm run start:external`. Он запускает только Express с настройками из `.env`.

## Если что-то пошло не так

- **Порт 3001 занят:** останови предыдущий запуск или укажи другой `PORT` в `.env`; поменяй адрес API во фронтенде.
- **Порт 55432 занят:** укажи другой `LOCAL_PG_PORT` в `.env`. Если именно эта база осталась запущенной после аварийной остановки, сначала выполни `npm run db:stop` из папки сервера.
- **PostgreSQL не найдена:** добавь её bin в `PATH` либо укажи `PG_BINDIR`. Например, для Homebrew: `/opt/homebrew/opt/postgresql@17/bin`.
- **Не удаётся загрузить npm-пакеты:** проверь интернет и доступ к `registry.npmjs.org`, затем повтори запуск.
- **Фронтенд на другом домене:** явно добавь его origin в `CLIENT_ORIGINS`. При HTTPS нужен также HTTPS/WSS-доступ к серверу через хостинг или reverse proxy.
- **Браузер пишет CORS / Origin:** открывай фронтенд через Vite на localhost, не как `file://`.
- **После обновления основной версии PostgreSQL не открывается старая база:** понадобится миграция PostgreSQL. Не удаляй `.local/postgres`, если нужна история.

`.local/postgres` — настоящие данные, `.local/postgres-password` — сгенерированный пароль локальной базы, `.local/postgres.log` — журнал. Не удаляй и не публикуй `.local`; она исключена из Git вместе с `.env` и `node_modules`. Сервер слушает только локальный интерфейс по умолчанию.

## Проверки

```sh
npm test
```

Интеграционные тесты сами запускают **отдельную временную PostgreSQL на свободном порту**, проверяют REST и несколько WebSocket-клиентов, затем останавливают и удаляют тестовую базу. Твоя история не затрагивается.

## Границы первой версии

Имена не уникальны и не защищены паролем: это учебный вход под ником, не аутентификация. Все комнаты и история публичны для клиентов сервера. Регистрации, файлов, звонков, редактирования/удаления сообщений, индикатора печати и статусов прочтения пока нет. Сервер рассчитан на **один процесс**; рассылка между несколькими экземплярами не реализована.

Для портфолио укажи честно: backend предоставлен отдельно, твоя работа — React-фронтенд и интеграция с API.
